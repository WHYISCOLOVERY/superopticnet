## Known baseline blockers

1. Payment DB write and RADIUS synchronization are not represented as a durable state machine.
2. Finance render can execute schema/seed writes.
3. NOC controller guards are not sufficient for direct service calls.
4. Production mock customer/message fallbacks exist.
5. Secret readiness is incomplete; see `02_SECRET_TRANSITION_PLAN.md`.

## Comparison rule

Post-change verification must compare:

- schema fingerprint and applied migration versions;
- payment/account/RADIUS counts before and after rollback-safe tests;
- operation/audit deltas by test correlation ID;
- the same regression tests plus the new Stage 0 suites.
