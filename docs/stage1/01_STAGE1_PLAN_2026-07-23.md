# Stage 1 - Service and data contract plan

Date: 2026-07-23
Timezone: Asia/Baku
Status: implementation baseline

## Scope

Stage 1 is limited to backend service and data correctness:

1. Close operation permission-map gaps and fail closed for unknown write actions.
2. Make `finance_entries` the canonical income/expense ledger.
3. Make e-invoice import atomic and idempotent.
4. Connect payable HR records to the canonical Finance ledger.
5. Add an explicit return -> inspection -> repair/RMA inventory contract.
6. Apply one timezone-aware date contract to Finance and Statistics queries.

Large UX changes, Message Center redesign and Agent Workspace are explicitly out
of scope for this stage.

## Migration

Add `20260723_020_stage1_service_data_contracts`:

- Extend `finance_entries` with source, employee, idempotency, correlation,

## Service contracts

### Permissions

Every POST action dispatched by `operations-center.php` must be present in the
operation action map. Unknown actions are denied. Admin keeps global access;
module roles retain their existing scoped access.

### Finance ledger

Manual income, manual expense and HR-generated expense records write to
`finance_entries`. A source record can create at most one posted ledger row.
Audit rows include source and correlation identifiers.

### E-invoice

One normalized request hash identifies a batch. Replaying the same request
returns the existing batch and creates no additional debt, invoice or ledger
rows. A batch transaction either persists every validated row or persists none.

### HR to Finance

Only payable HR statuses can create an expense. The source key
`hr:<record_type>:<record_id>` is unique. Retry returns the existing Finance
entry.

### Inventory

The allowed repair states are:

`pending -> in_repair -> repaired|rma|scrapped|cancelled`

An inspection is required before repair/RMA registration. Every state change
requires an actor, reason, idempotency key and audit entry.

### Dates

All ranges use `app_timezone()`. DATE columns use inclusive start/end dates.
DATETIME columns use a half-open interval `[start_at, end_exclusive)`. Invalid
custom ranges return a validation error rather than silently widening the
query. Future rows are excluded from operational totals and counted separately.

## Tests

Required before acceptance:

- Migration dry run, apply and registry checksum verification.
- Permission matrix including unknown-action denial.
- Manual Finance income and expense persistence.
- HR expense retry idempotency.
- E-invoice duplicate replay and forced-failure rollback.
- Inventory invalid and valid state transitions.
- Date boundary, timezone and future-row anomaly tests.
- Existing Finance, HR, Inventory and Statistics smoke tests.
- Full-system regression.
- Production test-data cleanup dry run.

## Rollback

1. Disable the four Stage 1 feature flags.
2. Stop Stage 1 writers before schema rollback.
3. Verify whether any Stage 1 source, batch or repair rows exist.
4. Migration `down` refuses destructive rollback when Stage 1 data exists.
5. With zero Stage 1 rows, remove only the new table, indexes and columns.
6. Restore the pre-migration database backup only if schema rollback cannot be
   completed safely.

No existing credential, payment, customer, inventory or audit record is removed
as part of Stage 1 rollback.
